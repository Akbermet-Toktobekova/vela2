## Requirements and decisions

Preserves SPEC feedback lifecycle and D-001/D-005/D-010; integrates coordinator-owned D-011 local-only access middleware before JSON parsing, removing permissive CORS. No canonical AS records, catalog IDs, shared contracts, formulas, financial scoring rules, or prototype-policy values changed.

Explicit unknown/missing recommendation IDs return 404. Feedback on superseded PI or nonlatest recommendations returns 409. Completed/declined/expired recommendations cannot be mutated; Complete requires accepted or adjusted state. A second Complete returns 409 before mutation. Complete uses stored validated amount, rejects overrides, and rechecks the candidate against current PI. Proposed allows accept/adjust/decline; accepted/adjusted allows adjust/decline/complete, adjusted also allows accept.

Completion's recommendation write, feedback and PI update share one SQLite savepoint transaction; PI save uses a nested savepoint. Derived views rebuild through the existing snapshot builder. Same-currency debt payment bookkeeping uses the explicitly selected known personal source account, reduces its balance and debt principal, and never moves real funds. Unknown source/currency returns 409 `COMPLETION_NEEDS_DATA` rather than selecting another account or inventing FX. Savings allocation verifies the goal and source actually exist with matching currency; no dangling `goal_cushion`/`acc_primary` IDs are manufactured.

Fresh review after completion is returned in `nextCycleResult`; the completed record remains accessible by ID. If that review fails after commit, HTTP remains 200 `COMPLETED` with authoritative snapshot and `reviewPending: true`, plus a safe retry message. Raw upstream errors are not exposed. Today retries freshness. Today refreshes when PI/trace/recommendation versions disagree; if concurrent changes prevent alignment it returns 409. UI agent was informed of response/error/pending contracts.

## Limitations / edge cases

- Adjust validates amount but does not rerun scoring or regenerate historical decision trace. UI must suppress historical financial effects/scores after adjustment (coordinated with T-09B).
- Reuses existing snapshot builder, including documented fixed date/freshness assumptions; no new financial date rules introduced.
- A001 contract has no paid-minimum/next-due advancement field. No next due date or paid rule invented; issuer reconciliation remains outside scope.
- Completion retains existing PI effects for savings allocation, debt payment and scheduled transfer pause; other confirmations retain existing behavior. No bank integration added.
- Pending post-completion review retries when Today loads; durable background review job/retry queue remains absent.
- Local loopback restrictions are prototype access control, not multi-user production authentication.
- No additional formulas, policy thresholds or AS approval changes introduced. Mandatory scenarios exercise existing fact/policy guards; full integration review remains coordinator responsibility.
