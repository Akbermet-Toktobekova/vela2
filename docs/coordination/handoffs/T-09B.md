## Behavior delivered

- Backend feedback waits for a successful response before changing local recommendation state. Non-2xx responses, malformed success and unavailable transport reject; UI shows failure rather than a local success.
- A synchronous feedback lock and disabled controls prevent repeated clicks while an operation is pending. Modals close only after confirmed success.
- Backend financial snapshots replace browser-owned financial collections after feedback; user identity, chat and local history are preserved. Server-computed debt/balance/allocation effects are not replayed in browser code. `nextCycleResult` takes first position in Today; completion without a new cycle still merges completed recommendation and snapshot.
- An unresolved backend response leaves a per-user recovery marker. Recovery reads authoritative Today before a subsequent PI write/reload can overwrite a committed completion. Known client rejections can clear the marker; unavailable server retains it.
- `reviewPending` after a committed completion is shown as saved completion with pending-review notice; it is not shown as a failed monetary update.
- Financial synchronization excludes recommendation, feedback and chat-only updates. Those state changes no longer create a fresh snapshot/review loop.
- Today distinguishes backend recommendations from local prototype suggestions. Null stability displays “Not evaluated,” never a fabricated 100%. Adjusted amounts hide original evaluation scores until another review.
- Generic financial actions use Accept / Mark action completed, not Safety Cushion reservation labels. Complete requires accepted/adjusted status. Backend-owned actions use stored amount and account; A007's stored account is displayed read-only.
- Removed local fabricated F017/F018/normalization/complexity/provenance metadata and invented offline monetary suggestion generation. The explicit seeded demo suggestion remains, with no server metrics. Fresh offline custom profiles receive data/verification hints, not made-up monetary amounts.
- The Adjust input has no hardcoded €40 recommendation or 10/50/100 amount defaults. Backend validates requested amounts. Local demo completion validates finite positive amount, existing goal and personal same-currency account with sufficient recorded cash.
- Safe-to-spend Assistant intent takes precedence over broad savings/spending keyword branches.
