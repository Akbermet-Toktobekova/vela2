## Requirements and decisions
Implements D-014 through BetaEngineRepository from C02. Normal review uses the persistent encrypted repository and the existing ReviewOrchestrator without unconditional forceRefresh. Existing financial formulas, catalogue IDs, AS statuses and prototype parameters were not changed.

Review returns version, policyVersion, full opted-in decision/recommendation/trace, traceId, per-call provider provenance, agent freshness, and the current snapshot. Old/non-opted-in profiles remain gated. getCurrent(), getTrace(), checkFreshness() support authenticated HTTP integration. Freshness uses the current PI version and policy bundle version, next UTC-day boundary (existing evaluation suppression/day contract), and existing agent cache max age from prototype policy. No new financial thresholds were introduced.

feedback() calls existing submitFeedback rather than replaying monetary math. Persistent request fingerprints and in-flight dedup prevent duplicate acceptance/completion effects. Explicit expectedVersion conflicts are preserved. Existing repository transaction handling and snapshot versions remain authoritative. Completion can trigger an existing engine follow-up review, and accepted intentions leave balances unchanged.

Chat remains structured fact selection but its facts now include the actual opted-in decision, rationale, impacts, candidate validation alternatives, trace references and feedback history. It never creates a new unchecked monetary action or generates new numeric effects. Requests for financial action explain the current checked action, or ask the user to refresh Today when none is available. Existing privacy scrubbing, consent, request dedup and provider failure visibility remain.

## Integration notes and limits
Repository abort() rejects late engine writes after timeout or PI-version change. Publication happens only after bounded review returns and the current consent/version is checked. A timeout cannot cancel requests already issued by the legacy SDK, but cannot publish a late beta decision.

Root owns HTTP and scheduler integration, deletion/purge of engine documents, UI and physical device acceptance. No new standalone SQL database is created by this module. Runtime old API route compatibility and comprehensive cross-process concurrency are coordinator checks.
