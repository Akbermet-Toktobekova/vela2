# Seven-block integration interface

BetaState adds experimentalRecommendations:boolean (default false on old records). PUT /state body may set it, explicit opt-in UI required. Existing aiConsent independent.
BetaAnalysis constructor remains (BetaStore,BetaFinancial,provider?,options?). review(user,version,forceRefresh=false) returns full {version,status,snapshot,decision,recommendation,trace,traceId,policyVersion,provenance,...}. Gate recommendation if experimental false only; preserve decision internally. Persist results and cache in encrypted BetaStore through BetaEngineRepository. No in-memory SQLiteStore engine during normal runtime.
Repository module exports BetaEngineRepository(store:BetaStore,user:{id,name,email},financial:BetaFinancial). Implements existing orchestrator storage methods structurally, enforcing user scope. Expose engine store interface from reviewWorkflow.ts using Pick<SQLiteStore,...required public methods> to avoid concrete private-class restriction. Agent persistence owns interface change only. Repository must treat beta seed as authoritative, CAS version guard, deterministic version string from beta number; no copying incoming snapshots over newer user state. All records AES-GCM via BetaStore. Behavior classification/confirmations copied back only at current version, preserve user-confirmed values. On feedback actual PI changes bump numeric beta version and preserve base seed.
BetaAnalysis adds feedback(user,input) -> existing SubmitFeedbackResult + {version,state} (same envelope optional) and getCurrent(user), checkFreshness(user) -> {needed:boolean,nextCheckAt?:string}. Engine agent owns analysis implementation and tests, coordinator app route integration and scheduler. feedback input {recommendationId,action,adjustedAmount?,note?,requestId?,expectedVersion?}. User isolated. Repeated accept/complete idempotent and stale conflicts, use existing orchestrator submitActionFeedback signature inspect.
GET state includes analysis and recommendation from latest current analysis. POST review accepts optional forceRefresh (default false); job args include forceRefresh. Feedback POST must call analysis.feedback instead of release gate. Coordinator queues after PUT/classification/import/delete and startup/freshness checking. No invented financial thresholds. Use existing policy freshness deadlines and configured next expiry.
UI uses env.experimentalRecommendations; PUT sends {expectedVersion,state,aiConsent,experimentalRecommendations}. Feedback route accepts UI's existing action/amount alias, coordinator normalizes. Goal allocation release gate separate user bookkeeping remains unless existing calculator/checker used, never fake money effects. UI must not calculate monetary totals outside server snapshot.
