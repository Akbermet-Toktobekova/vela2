## Requirements and decisions

D-014 experimental seven-block integration. Engine documents persist immutable original snapshots per numeric beta version, agent cache, evaluation history, candidates/checker through traces, decisions, recommendations, pending commitments, feedback, messages and FX cache. Persistent storage uses BetaStore AES-GCM/DPAPI foundation.

Constructor API: new BetaEngineRepository(store,user,financial). Additional lifecycle helpers abort() and syncFromSnapshot(snapshot,expectedVersion). All engine writes reject after abort or newer beta version. Reads expose latest profile version to the stale-publication guard. getPIState never auto-seeds demo. Seed is authoritative. Feedback savePIState increments beta numeric version while preserving latest recommendations and feedback history, and nested savepoints provide atomic rollback.

Derived classifications and new confirmations merge without replacing explicit user-confirmed classifications. The immutable snapshot remains original for each version, preserving cache-input semantics while derived data is copied to current PI. Recommendations and feedback are mirrored to current seed without changing financial version for status-only updates.

No canonical AS statuses, formulas, action IDs or prototype thresholds modified. Pending commitment selection reuses existing SQLiteStore semantics.

## Integration limitations

File deletion must invalidate/purge relevant engine records as coordinated with root. Account deletion naturally clears all documents via BetaStore.deleteUser. Late writes fail closed when versions differ. The adapter does not schedule jobs or issue consent/release decisions; those belong to beta analysis/routes. Physical mobile verification remains coordinator scope.
